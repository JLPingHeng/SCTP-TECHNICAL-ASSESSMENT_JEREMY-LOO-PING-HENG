# Question 5 — Operating Systems, Terminals, and Shells

**Format:** Short Answer

---

> Answer in your own words, 1-3 sentences each. Writing it yourself is the point.


**(a)** What is a **kernel**, in plain language? (One or two sentences. No textbook definition copied in; explain it as you understand it.)

**Answer:**
_A kernel is the core component of an operating system that manages hardware resources. It is the primary bridge between software and hardware - by allowing software (i.e terminal) to interact with hardware (i.e CPU, RAM, and storages)._

---

**(b)** A classmate says:

> "I installed WSL, so now I have two completely separate operating systems, Windows and Linux, running side by side, each totally independent."

Is this accurate? Briefly explain why or why not.

**Answer:**
_This is inaccurate because WSL is tightly integrated into Windows rather than being independent; Windows dynamically shares its CPU and RAM with Linux, and both environments freely share the same file system and network - Linux can easily reach over and open the Windows files, and Windows can open the Linux files. They aren't locked away from each other._

---

**(c)** Explain the difference between a **terminal (emulator)** and a **shell**, and give one example of each.

**Answer:**
_A terminal emulator is the visual graphical user interface (GUI) window that captures what users type on their keyboard, sends those raw characters to the shell, and displays the resulting text output back to users on the screen. (i.e. Windows Terminal), whereas a shell is the underlying program that sits inside the terminal window, reads the text commands users submit, processes the logic, and communicates with the OS kernel to run the requested actions. (i.e. Zsh)._
